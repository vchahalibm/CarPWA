# DriveDeck (CarPWA)

Pure HTML/CSS/JavaScript PWA. **No frameworks, no bundler/build step, no npm dependencies** in the web app. The one exception is `desktop/`, the Electron wrapper (Mac DMG, built by `.github/workflows/desktop.yml`), which has its own `package.json`. It serves the unchanged web files from `app://drivedeck/`; never add desktop-only code paths to the web files beyond feature checks (`IS_DESKTOP_APP` in js/voice.js). Third-party code is vendored, never installed: MapLibre GL JS 5.x (UMD build) in `vendor/maplibre/` (keep to 5.x: 6.x is ESM-only and can't load as a classic script), hls.js (light UMD build, loaded on first HLS stream) in `vendor/hls/`, pdf.js (legacy ESM build, loaded with dynamic `import()` on first PDF) in `vendor/pdfjs/`, PptxViewJS + JSZip + Chart.js (UMD, loaded on first .pptx) in `vendor/pptx/`, model-viewer (UMD) in `vendor/model-viewer/`, MediaPipe Tasks Vision (ES module build + models) in `vendor/mediapipe/`, three.js + three-vrm as one prebuilt ESM bundle in `vendor/three-vrm/` (rebuild steps in its README), built-in 3D models (CC0 only, credited in `vendor/models/LICENSE.md`; listed in `BUILTIN_MODELS` in js/media.js). Load them lazily, never in `SHELL`. Exception: transformers.js for on-device Whisper and kokoro-js for the reply voice are loaded lazily from pinned jsDelivr URLs (`TRANSFORMERS_URL`, `KOKORO_URL` in `js/voice.js`) with dynamic `import()`, together with their ONNX runtimes and models, and cached by the service worker. Vendoring it trips GitHub secret scanning (a false positive in the minified bundle).

- Run: `python3 -m http.server 8000` from the repo root. Check: `for f in js/*.js sw.js desktop/main.js; do node --check $f; done`. Desktop: `cd desktop && npm install && npm start`.
- Classic scripts sharing globals, loaded in order: `js/log.js` (debug log, loaded first so it catches everything), `js/events.js` (the `Bus` event bus), `js/routing.js` (routing/search providers, the `Routing` object), `js/app.js` (app logic), `js/modes.js` (Map/3D/AR/HUD modes), `js/dash.js` (dashboard layouts, cluster styles, widgets, sensors), `js/voice.js` (speech-to-text, spoken replies, listening box, conversation log, Assistant widget), `js/commands.js` (voice/typed commands: matching, defaults, built-in actions, the Settings › Voice commands editor; defines `handleCommand`), `js/duplex.js` (Conversation mode (beta): `AudioEngine` owns the microphone, AudioContext and audio session for the whole conversation, `Convo` does turn-taking, echo rejection and barge-in with Moonshine/Whisper; while `Convo.active`, play replies through `AudioEngine`, never a separate player), `js/widgets.js` (`Actions`, `Links` and Settings › Widget links), `js/radio.js` (the radio player and widget), `js/media.js` (document, video, web page and 3D widgets; device files in IndexedDB via `Files`), `js/avatar.js` (VRM avatars in the 3D widget: lip-sync from `voice.audio`, gestures via `Avatar.gesture/face`), `js/vision.js` (Camera widget, object detection worker, alerts, “what do you see”), `js/stage.js` (Stage mode: `Stage.on` is true when Settings › Mode is Stage and the car isn't moving; Drive mode means avatar expressions only, no body gestures; captions; cameras per mode via `Camera.want()`), `js/script.js` (Scripts: avatar-led presentations; the runner `Script`, saved `Scripts`, the editor `ScriptUI`; format in docs/scripts.md. Script steps are `Actions`, so new widget abilities become scriptable by defining actions; make actions that load something async and return the promise), `js/people.js` (People on Stage: MediaPipe hands/pose/face in its own module worker; the presenter is claimed with a gesture sequence; emits `people.gesture`/`people.claim`; `VrmAvatar.look()`; `People.spoke()` gates conversation speech to the presenter), `js/webdrive.js` (Web steps: record/replay clicks on the user's own pages in a web widget, directly for same-origin pages or through `bridge/drivedeck-bridge.js`, which only answers origins in its `data-allow`; never record password-like fields; only drive pages the user owns, no proxies or injection into other sites), `js/debug.js` (wraps app functions to log them, and the Settings › Logs tab; loaded last). Code that runs while app.js loads (e.g. `?view=settings`) must guard globals from later files with `typeof`. Later files use earlier files' globals; don't redeclare a global name (e.g. `rad`, `deg`). Styles in `css/styles.css`, markup in `index.html`. Keep the existing idiom: `$`/`$$` helpers, `store` for localStorage (keys prefixed `dd.`), icons in the `I` map rendered via `svg()`.
- Keep all URLs relative so the app works under a sub-path (GitHub Pages serves it at `/CarPWA/`).
- When changing any file in `SHELL` in `sw.js`, bump `VERSION`. Add new static files to `SHELL`.
- Car-first UI: tap targets ≥ 56px, respect the "hide while driving" setting, and keep both dark and light themes working (tokens on `:root` / `[data-theme="light"]`).
- Widgets live in lists keyed by `where` (`left`/`right` beside the cluster, `<style>.p<n>` for cluster panes with `@` marking the pane itself, `pg<n>` for widget pages); use `Dash.list/setList` and the `add/adds/rm/up/down/swap` commands.
- Widgets working together: emit app events with `Bus.emit(name, { value })` (declare new ones with `Bus.define`); expose what a widget can do with `Actions.define(id, { group, name, arg, run(value, say) })`, so voice commands (Then › Do a widget action) and links can run it; widgets react to events with `W[type].on = { event(data, id) {} }`. Widget types that can be added more than once set `multi: true`; their ids are `type~xxxx`, settings in `Wcfg`, edited by `W[type].config(id)`. Look widget types up with `W[wtype(id)]`. Media that must survive dashboard re-renders (audio) lives outside the widget, like `Radio.el`. `Dash.show()` (opening the dashboard) redraws only when `Dash.key()` changed, so iframes keep playing; don't put fast-changing state (a PDF page) in `Wcfg`, which is part of that key. Widgets fill themselves after a redraw on the `dash.rendered` event.
- Hand-offs to native apps go through `openExternal(scheme, webFallback)`; sample contacts never dial.
- New voice abilities: add a `BUILTINS` entry and a `DEFAULT_COMMANDS` entry (phrases) in `js/commands.js`, not regex in app.js. Replies go through `say(msg, then, { leaves })`; set `leaves` when the action opens another app so the reply finishes first. Keep the phrase tests passing (a phrase should not steal another command's words).
- Debug log: log anything useful for chasing bugs with `Log.i/d/w/e(category, message, data)` (categories like `stt`, `tts`, `audio`, `mic`, `cmd`, `nav`, `net`). It's a no-op unless debug mode is on (`?debug=<key>`, or 7 taps on the version row in Settings; only the key's SHA-256 is in `js/log.js`). Never log secrets; `Log` hides keys/tokens. Voice playback options for testing on a phone live in `Diag` (js/voice.js).
- Full-duplex voice design: `docs/duplex-voice.md`. Memory: `docs/memory-strategy.md`. Each on-device model runs in its own worker (`createWhisper`, `kokoroWorker` in js/voice.js, `Vision` in js/vision.js, `People` in js/people.js); unloading ends the worker, the only way iOS gets the memory back. Load big models through `Heavy`, make room with `Budget.room(name, need)`, register them with `Budget.add` and wrap the load in `Budget.guard(label, …)` so a crash during it is remembered.
- The camera is one shared stream (back in Drive, front/webcam on Stage, per Settings › Cameras): get it with `Camera.get(user)` and give it back with `Camera.release(user)` (js/modes.js); never call `getUserMedia` for video directly. Detection models live in `VISION_MODELS` (add Apache-licensed choices there; the user picks in Settings).
- Routes are normalised by `js/routing.js` (`coords`, `cum`, `tcum`, `steps`, `segLimit`); add new providers there, not in app.js.
- Dashboard gauges bind to live values via `data-t`/`data-arc`/`data-rot`/`data-w`/`data-tf`/`data-show`/`data-html`/`data-cls` keys from `vals()` in `js/dash.js`. Only show data the phone really has.
- Never use Apple names, logos or assets.
- `tools/trainer/` is a separate local tool (Python server, stdlib HTTP + torch/torchvision; plain HTML/JS page in `ui/`) for labeling, capturing the user's own pages and training detectors exported as ONNX; it isn't part of the PWA or `SHELL`. Keep the default engine permissively licensed (torchvision); Ultralytics stays optional and labelled AGPL.
- `docs/prototype.html` is the original reference prototype. Don't edit it.
