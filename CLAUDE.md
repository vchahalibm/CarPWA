# DriveGen (PWA) and StudioGen (desktop) — internally DriveDeck (CarPWA)

User-facing names come from `APP_NAME` (js/log.js: 'StudioGen' in Electron, 'DriveGen' on the web); never hard-code a product name in UI text. Internal ids keep `drivedeck`/`dd.` (storage, `DriveDeckDesktop`, `app://drivedeck`).

Pure HTML/CSS/JavaScript PWA. **No frameworks, no bundler/build step, no npm dependencies** in the web app. The one exception is `desktop/`, the Electron wrapper (Mac DMG, built by `.github/workflows/desktop.yml`), which has its own `package.json`. It serves the unchanged web files from `app://drivedeck/`; never add desktop-only code paths to the web files beyond feature checks (`IS_DESKTOP_APP` in js/voice.js). Third-party code is vendored, never installed: MapLibre GL JS 5.x (UMD build) in `vendor/maplibre/` (keep to 5.x: 6.x is ESM-only and can't load as a classic script), hls.js (light UMD build, loaded on first HLS stream) in `vendor/hls/`, pdf.js (legacy ESM build, loaded with dynamic `import()` on first PDF) in `vendor/pdfjs/`, PptxViewJS + JSZip + Chart.js (UMD, loaded on first .pptx) in `vendor/pptx/`, model-viewer (UMD) in `vendor/model-viewer/`, MediaPipe Tasks Vision (ES module build + models) in `vendor/mediapipe/`, three.js + three-vrm as one prebuilt ESM bundle in `vendor/three-vrm/` (rebuild steps in its README), built-in 3D models (CC0 only, credited in `vendor/models/LICENSE.md`; listed in `BUILTIN_MODELS` in js/media.js). Load them lazily, never in `SHELL`. Exception: transformers.js for on-device Whisper and kokoro-js for the reply voice are loaded lazily from pinned jsDelivr URLs (`TRANSFORMERS_URL`, `KOKORO_URL` in `js/voice.js`) with dynamic `import()`, together with their ONNX runtimes and models, and cached by the service worker. Vendoring it trips GitHub secret scanning (a false positive in the minified bundle). The same goes for ONNX Runtime Web (`ORT_URL` in js/voice.js), used for the user's own models (`UiDetect` in js/webdrive.js: the screen-element detector from tools/trainer, the visual fallback for web steps in the desktop app).

- Run: `python3 -m http.server 8000` from the repo root. Check: `for f in js/*.js sw.js desktop/main.js; do node --check $f; done`. Desktop: `cd desktop && npm install && npm start`. Multi-device tests: `node tests/tandem/run.mjs [--auto] [--hold]` (journeys in tests/tandem/journeys.mjs, add acts as features land; guide docs/tandem-guide.html; tests/tandem/README.md; the page hook is `Tandem` in js/linktest.js, steps only from its fixed `STEPS` list, never code sent over the network).

- Motions are written in VRM 0's normalized-rig convention; VRM 1 rigs (Maya, Leo, Seed-san) have x and z turns of the opposite sign: `AvatarInstance.nat()` converts when writing bones, and mocap converts back. Face channels in motions are `$a:<ARKit name>` (played straight on avatars with the 52 shapes, `inst.sync`, else mapped by `arkitToVrm`). New avatars: VRM files in `vendor/models/` listed in `BUILTIN_MODELS` (js/media.js), credited in `vendor/models/LICENSE.md`; Rocketbox conversion in tools/avatars.
- App steps inside a browser widget: input must go to the `<webview>` (`webview.sendInputEvent`/`WebDrive.tap`), never the window (it doesn't reach the page); the window picture misses parts of webviews, so `AppSteps.screen()` draws each `webview.capturePage()` in. Text inside pages comes from the bridge's `findText`.
- StudioGen updates itself (`desktop/updater.js`, docs/desktop-updates.md): web files from a signed bundle, the shell only when `desktop/package.json` version goes up. Changes to `desktop/` (preload powers, main process, Electron) need that version bump; everything else ships as a web update. `web-version.json` is generated (CI); never commit it. Avatars, MediaPipe models and WASM are lazy in the desktop app (`LAZY`/`lazyFile` in desktop/updater.js): not packaged, downloaded on first request at the build's commit and checked by SHA-256; new big vendor files of that kind should match `LAZY`.
- Keep all URLs relative so the app works under a sub-path (GitHub Pages serves it at `/CarPWA/`).
- When changing any file in `SHELL` in `sw.js`, bump `VERSION`. Add new static files to `SHELL`.
- Car-first UI: tap targets ≥ 56px, respect the "hide while driving" setting, and keep both dark and light themes working (tokens on `:root` / `[data-theme="light"]`).
- Widgets with `float: true` (camera, model) can float over the others: `Dash.float(id, on, rect)`, kept per layout in `dd.wfloats` as [x, y, w, h] fractions, and then in no list. List sizes are `[w, h]`: on widget pages in half cells (grid tracks are half cells), in columns a flex share (fractions allowed); column widths in `dd.sideW`.
- Widgets live in lists keyed by `where` (`left`/`right` beside the cluster, `<style>.p<n>` for cluster panes with `@` marking the pane itself, `pg<n>` for widget pages); use `Dash.list/setList` and the `add/adds/rm/up/down/swap` commands.
- Widgets working together: emit app events with `Bus.emit(name, { value })` (declare new ones with `Bus.define`); expose what a widget can do with `Actions.define(id, { group, name, arg, run(value, say) })`, so voice commands (Then › Do a widget action) and links can run it; widgets react to events with `W[type].on = { event(data, id) {} }`. Widget types that can be added more than once set `multi: true`; their ids are `type~xxxx`, settings in `Wcfg`, edited by `W[type].config(id)`. Look widget types up with `W[wtype(id)]`. Media that must survive dashboard re-renders (audio) lives outside the widget, like `Radio.el`. `Dash.show()` (opening the dashboard) redraws only when `Dash.key()` changed, so iframes keep playing; don't put fast-changing state (a PDF page) in `Wcfg`, which is part of that key. Widgets fill themselves after a redraw on the `dash.rendered` event.
- Hand-offs to native apps go through `openExternal(scheme, webFallback)`; sample contacts never dial.
- New voice abilities: add a `BUILTINS` entry and a `DEFAULT_COMMANDS` entry (phrases) in `js/commands.js`, not regex in app.js. Replies go through `say(msg, then, { leaves })`; the voice is `Voice.ttsMode()` (settings.tts 'auto': Phonon (js/phonon.js) when downloaded and keeping up here, else the device voice via `PhoneVoices`; 'phonon', 'phone', 'off', or 'neural' = Kokoro, an optional download now; other languages than English use the device voice; `Voice.checkVoices()` times them), and `speakPhone` must see `onstart` within 1.5 s (reset and retry, then `voiceless`); set `leaves` when the action opens another app so the reply finishes first. Keep the phrase tests passing (`node tests/phrases.cjs`, also run by CI; a phrase should not steal another command's words). Matching is exact first, then near-miss spelling, then loose (`Commands.loose`: a phrase that covers most of what was heard, scored by word weight; at `LOOSE_RUN` it runs, from `LOOSE_ASK` it asks “Did you mean …?” and `Commands.pending` takes the yes/no). The phone recognizer's other guesses (`alts`) are tried too.
- Debug log: log anything useful for chasing bugs with `Log.i/d/w/e(category, message, data)` (categories like `stt`, `tts`, `audio`, `mic`, `cmd`, `nav`, `net`). It's a no-op unless debug mode is on (`?debug=<key>`, or 7 taps on the version row in Settings; only the key's SHA-256 is in `js/log.js`). Never log secrets; `Log` hides keys/tokens. Voice playback options for testing on a phone live in `Diag` (js/voice.js).
- Scripts and agent tasks: any change to their format, steps, editors or behaviour also updates `docs/scripts-and-tasks-guide.html` (the step-by-step guide) and the LLM build prompt (copyable from Settings › Scripts & tasks), in the same change.
- Requirements baseline (the user's view, with status per feature): `docs/requirements.html` (rows in `REQS`, screenshots in `docs/req/`); update a row's status when a feature lands.
- What comes next, in order: `docs/roadmap.md`. Full-duplex voice design: `docs/duplex-voice.md`. Memory: `docs/memory-strategy.md`. Each on-device model runs in its own worker (`createWhisper`, `kokoroWorker` in js/voice.js, `Vision` in js/vision.js, `People` in js/people.js); unloading ends the worker, the only way iOS gets the memory back. Load big models through `Heavy`, make room with `Budget.room(name, mb, need)` (priorities in `Budget.prio`: a model needed now unloads only lower-priority ones; false when it can't fit, so don't load it), register them with `Budget.add` and wrap the load in `Budget.guard(label, …)` so a crash during it is remembered.
- The camera is one shared stream (back in Drive, front/webcam on Stage, per Settings › Cameras): get it with `Camera.get(user)` and give it back with `Camera.release(user)` (js/modes.js); never call `getUserMedia` for video directly. Detection models live in `VISION_MODELS` (add Apache-licensed choices there; the user picks in Settings).
- Routes are normalised by `js/routing.js` (`coords`, `cum`, `tcum`, `steps`, `segLimit`); add new providers there, not in app.js.
- Dashboard gauges bind to live values via `data-t`/`data-arc`/`data-rot`/`data-w`/`data-tf`/`data-show`/`data-html`/`data-cls` keys from `vals()` in `js/dash.js`. Only show data the phone really has.
- Never use Apple names, logos or assets.
- `tools/trainer/` is a separate local tool (Python server, stdlib HTTP + torch/torchvision; plain HTML/JS page in `ui/`) for labeling, capturing the user's own pages and training detectors exported as ONNX; it isn't part of the PWA or `SHELL`. Keep the default engine permissively licensed (torchvision); Ultralytics stays optional and labelled AGPL.
- `docs/prototype.html` is the original reference prototype. Don't edit it.
