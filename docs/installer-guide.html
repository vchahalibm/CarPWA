The installer: everything that runs in containers

naomuse-install sets up what runs in containers: on your Mac, NaoMuseHive, home Node-RED behind its dark gate and the Worker image; on your Oracle machine, the dark relay, TURN and the cloud Node-RED. One file, nothing to install first. It checks the Mac, says what can and can't run there and why, lets you choose, then installs, starts and tests.

1. What it sets up

2. Getting it

In Terminal:

curl -fsSLo naomuse-install https://github.com/vchahalibm/CarPWA/releases/download/installer/naomuse-install
chmod +x naomuse-install
./naomuse-install

A download through the browser is held back by macOS, since the installer isn't notarised by Apple; curl's isn't. On the Mac with the source: node installer/build.mjs makes installer/dist/naomuse-install.

3. The screens

It draws on its own near-black ground, whatever your Terminal's colours: the name in big pixel letters (smaller when the window is short), and a row of steps showing where you are: Check › Choose › Install › Test (or Remove when uninstalling).

Check

Each check gets a ✓ (fine), ! (works, with a note), ✗ (can't) or • (good to know), with a line saying what it found.

What would you like to do?

Then a few details, only those it doesn't know yet: your mesh fingerprint (NaoMuse › Settings › Connections › Dark servers › Copy; it needs your mesh, so Mesh › Create a mesh first, and a NaoMuse with web 164 or newer: the Check screen says which yours has), and for an Oracle machine its public IP and SSH host. Then a summary of the steps, and enter to install.

Install

Each step in turn with a spinner, a progress bar, and the last lines of what's happening underneath. q twice stops in the middle; what's done stays done, and running it again carries on.

Test

That each part runs, and stays dark to a stranger. Then a last screen with where everything is and what to do next, which stays printed in your Terminal when you leave.

4. What it checks, and what that means

CheckWhat it means for you
This Mac, memory, free spacemacOS 13 or newer for the engines. All of it together needs about 1 GB of memory and 5 GB of disk.
Container engineOrbStack, Docker Desktop or Colima, if there's one. If not, you pick one to install (section 6).
InternetThe engine and images come from GitHub and Docker Hub.
IPv4 from outsideWhether your home's address is your own or shared with other homes (CGNAT). It asks the router; if the router won't say, it looks at the first hop past it. Shared is fine for everything here: it all dials out.
IPv6Your Mac's lasting IPv6 address (macOS also makes temporary ones that change daily). With IPv6, devices that have it too can often connect straight to your Mac, without TURN.
Ports8840 (the hive) and 8030 (the home gate) must be free, or already ours.
The Mac app, dark-server settingsWhether NaoMuse is installed (it starts Workers), and whether your settings exist yet (they're made while installing).

5. Why there's no TURN at home

TURN is the helper that carries a call or a camera's video when two devices can't reach each other directly. Running it at home, next to the cameras, would save Oracle's bandwidth. But on a Mac every container engine runs Linux inside a small virtual machine, and passes packets on as if they came from its own address. We tested it: a container saw every sender as 192.168.215.1, OrbStack's own address. TURN has to see who's really sending, so it can't work there.

What you get instead. With IPv6 (the checks say), devices that have it too can often connect straight to your Mac, with no TURN at all. Everything else goes through Oracle's TURN. Oracle gives 10 TB a month; a 2 Mbps camera watched non-stop through TURN uses about 650 GB. A Linux box at home (a Raspberry Pi) could run TURN properly later.

7. Home Node-RED, after installing

  1. naomuse-install --code prints a code. Paste it in NaoMuse › Settings › Connections › Dark servers. Before there's an Oracle machine it holds only the home gate.
  2. NaoMuseHive: Settings › Connections › NaoMuseHive › + Add a NaoMuseHive, with the address and admin code the last screen shows (it needs your mesh: Mesh › Create a mesh).
  3. Open beside Home Node-RED: your browser goes through the gate (the link works once) to Node-RED's login. The user is admin; the password comes from naomuse-install --passwords.
  4. What Oracle may ask home to do goes in ~/StudioGen-update-keys/dark/home/capabilities.json: one entry per thing, by name. Run the installer again after changing it. Flows for a switch and a camera still: stack/ORACLE.md, Part 4.

Give your Mac a fixed address in your router's settings, so the gate's address (for example http://192.168.1.105:8030) doesn't change.

8. Your Oracle machine

Create the VM and open its ports first (stack/ORACLE.md, steps A1 to A5). Then run the installer and tick Oracle machine. It asks for the machine's IP and SSH host, then:

  • makes the relay, TURN and link secrets and the random addresses, kept on your Mac;
  • builds the servers here for the machine's Arm processor, sends the images and settings over SSH (secrets travel only over SSH), and starts them;
  • knocks on them from outside the way a stranger would: the relay shut to strangers, TURN answering only address questions without a login, the gates a bare 404, only the door facing the internet.

Then paste the new --code in NaoMuse and DriveGen: it now holds the relay as well.

12. Uninstalling

Run it again and choose Uninstall. It lists what it finds (not just what it remembers), each with what removing it means; what isn't here is greyed out:

PartRemovedTicked at first
NaoMuseHive, Home Node-REDTheir containers, images and networksYes
NaoMuse WorkerThe image, and the Workers made from itYes
Oracle machine's serversOver SSH: its containers, images and ~/naomuse there. The VM itself stays: delete it in Oracle's consoleNo
Their dataYour flows, the hive's data, Workers' sign-ins (Docker volumes). Can't be undoneNo
Settings and secrets~/StudioGen-update-keys/dark/ only, never what's around it. The code in your apps stops workingNo
NaoMuseTo the Bin. Its settings, sign-ins and memory stay in ~/Library/Application Support/StudioGenNo
Container engineOnly one this installer installed (Colima removed, OrbStack to the Bin)No

When something that can't be put back is ticked (data, settings, the engine, the Oracle machine's servers), it asks for y rather than enter. Without the screens: naomuse-install --uninstall says what it would remove, and --uninstall --pick hive,home,data --yes removes it.

13. NaoMuse itself

The Check screen shows the app's version and the web files it runs (for example NaoMuse 0.19.0 · web 150), and what's published. On Choose, NaoMuse (the Mac app) is ticked when it isn't installed or a newer one is published. It reads update.json from the updates release, checks its signature with the publisher's key (the one the app itself uses), downloads the zip for your processor, checks its SHA-256, quits NaoMuse if it's running, moves the old one to the Bin and puts the new one in Applications. Downloaded this way, not through a browser, macOS doesn't hold it back. Web updates still come by themselves when the app starts.
