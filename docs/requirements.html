1. Vision: two apps, one code base

DriveGen (the web app, PWA)

On a phone in the car: an agentic system that talks with the driver, an alternative to CarPlay: dashboard, maps and navigation, voice, music and radio, calls and messages, camera alerts.

On an iPhone or iPad: both the in-car assistant and agentic presentations and interactive tech demos (Stage mode).

Tasks: connects to a StudioGen to run task scripts there and get the results back.

StudioGen (the desktop app, Electron)

Agentic presentations, interactive tech demonstrator, interactive desktop task agent, user-and-agent tandem tasks, interactive data steward and agentic data analyst, all through scripts.

Scripts drive the screen, web sites, the app and the computer itself (AppleScript on a Mac, PowerShell on Windows), partly in the background while the assistant keeps talking with you.

Hosts the heavy models and serves DriveGen devices.

Rules that apply everywhere: the same web code runs in both apps (feature checks only); everything works offline where it can; nothing personal leaves the device unless you send it; passwords, payment and one-time codes are never recorded; product names come from APP_NAME.

4.1 Script engine: from a list of steps to a conversation

  • Steps stay cards, but each step can also have: conditions (“if the task found errors”), variables ({task.result}, {heard.place}), and a loop (“repeat until the user says done”, “for each file”).
  • Background steps: any action can be marked in the background. The script carries on (the assistant keeps talking or listening); a job list shows what runs; a step can wait for a job, and a job finishing is an event that can move the script on or branch (“when the export finishes, tell me”). The assistant can announce progress between other steps.
  • Interactive (agent) scripts, a second kind of script: instead of a timeline, a set of things it can do, each started by phrases, gestures or events (intents). The assistant waits, listens (conversation mode), matches what you say or show to an intent with the existing forgiving matcher, runs its steps, reports, and waits again, looping until you end it (“that's all”, a gesture, a timeout). Intents can ask follow-up questions (“which month?”) and fill variables.
  • Later: a local language model (roadmap Phase E) to understand free-form requests and pick the intent and its values; the same intents stay the guard-rails of what it may do.

4.2 OS tasks (AppleScript and the Windows equivalent)

  • A new step kind Run on this computer: AppleScript or JavaScript for Automation on a Mac (osascript), PowerShell on Windows, with inputs from script variables and its output (text or JSON) back into variables the assistant can speak or show (a table widget).
  • Runs in the desktop app's main process, never in web pages; time limit and a Stop button; its output is logged.
  • Safety: the first run of each OS task shows its code and asks (“Allow always for this script?”); imported bundles that contain OS tasks are flagged like site helpers and need that approval again; macOS will ask once for Automation / Accessibility permission per app being controlled. DriveGen can only run tasks the StudioGen owner has marked available to paired devices.
  • A library of ready tasks to start from: open an app or file, read the frontmost window title, export from Numbers/Excel, read a folder, Finder actions, Mail drafts, Calendar events, Shortcuts (run a macOS Shortcut by name).

4.3 DriveGen ↔ StudioGen link

  • Pairing by QR code from StudioGen (roadmap Phase D); paired devices listed with Revoke.
  • DriveGen sees the tasks and scripts StudioGen offers, runs one (“run the sales summary on my Mac”), gets progress and the result spoken or shown; also the Mac's heavier models for an iPad on Stage.
  • On the same Wi-Fi it's direct. From a car on mobile data the Mac must be reachable: Tailscale (no server, free for personal use) or a small relay server (a cloud service to run and secure). See the questions.

4.4 Settings shaped by the app

  • Settings grouped by what you're doing: General (app, version, updates, storage and downloads, about), Assistant (avatar, voice, listening, conversation), Drive (DriveGen: dashboard, navigation, music, phone, camera alerts), Stage (layout, presenting, people tracking, cameras), Scripts & tasks, Connections (paired devices / Macs), Advanced (models, memory, logs).
  • StudioGen opens on Stage and hides Drive groups unless “Also use for driving” is on; DriveGen on a phone opens on Drive.

5. Avatars: choices to discuss

Default: one core anime avatar comes with the app (downloaded on first start); every other one is downloaded from Settings › Assistant › Avatars (a gallery with previews and licences) or added from a file. The Rocketbox people (Maya, Leo) stay supported but are not downloaded by default.

Where avatars come from, best first:

  1. VRM files (VRM 0 and 1; the VTuber standard): VRoid Studio exports, VRoid Hub downloads the author allows, BOOTH. Works today; only needs the upload check.
  2. A gallery we curate: CC0 or credit-only VRMs listed in the library index, downloaded on request and checked by SHA-256 (same as the lazy files).
  3. VRChat / Unity avatars: shipped as Unity packages (.unitypackage) with FBX and PhysBones; a browser can't import them directly. Path: the free UniVRM exporter in Unity (or the VRM add-on for Blender) turns them into VRM. We document the steps; optionally a converter in tools/avatars.
  4. GLB / FBX humanoids (Mixamo, Ready Player Me, MMD after conversion): load them with a bone-mapping screen that guesses the humanoid bones by name and lets you fix the rest; no expressions unless the file has blend shapes.
  5. VRoid Hub in the app: browse and download from inside the app needs a registered VRoid Hub app and sign-in, and their terms; possible later.

Upload check: on adding a file the app reads it and reports: humanoid bones found and missing (hips, spine, chest, neck, head, arms, hands, legs, feet, fingers), expressions present (blink, a/i/u/e/o, joy/sorrow…, ARKit 52), VRM version, size and polygon count (warns over a budget), licence fields from the VRM meta (commercial use, credit). Missing core bones: refused with the list; missing fingers or expressions: allowed with a note on what won't move.

6. Lower-body modes (mocap without legs)

Proposal: capture follows the upper body, hands, face and lips only, so you can sit or stand close to the camera; legs come from a chosen stance, mixed under the captured upper body (also usable on any motion and in scripts):

Stand: still, weight centred, tiny breathing sway. The default for capture.
Relaxed sway: slow weight shifts from foot to foot, knees soft.
Presenter walk: a few steps left or right and back, turning slightly toward the audience; a script can say “walk to the left side” (toward a widget).
Step in / step back: one step toward the audience for emphasis, and back.
Lean on one hip: casual contrapposto, swaps sides now and then.
Rooted with hips that follow: feet planted, hips turn and lean a little with the captured torso, so a twist or a bow looks natural.
Seated: for a desk scene (needs a chair or a cropped view).
Energetic: small bounce on the beat (celebrate, the radio dancing).

Capture control without walking back to the screen: start with a countdown, stop by voice (“stop”, “cut”) or a hand sign (both palms up, or the claim gesture), or a fixed length; the take is trimmed to where you started and stopped moving, with a trim bar in the review.
