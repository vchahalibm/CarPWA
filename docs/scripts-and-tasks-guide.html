Scripts and agent tasks: the step-by-step guide

How to make, change and fix scripts (presentations and sequences the assistant performs) and agent tasks (jobs the agent does when you ask in your own words), with what each step is for, how to set it up and when to use it, plus recipes for the harder cases. Both are made in Settings › Scripts & tasks in StudioGen; tasks that use web pages run on your Mac.

They work togetherA task can run a script (step Run one of my scripts: “present the keynote” from the car starts it on the Mac). A script can run a task (the action Run another task, in the Agent group of the script editor's action list). And a task can run other tasks in order. Both use the same step language, so what you learn here works in both.

The practice inbox

To try things safely, use the made-up mailbox at https://vchahalibm.github.io/CarPWA/labs/practice/inbox.html: a search box, a message list and a reading pane, built like Outlook on the web (the same kinds of labels and roles), with nothing behind it. The recipes below were run on it; the pictures are from those runs.

Make a script

  1. Settings › Scripts & tasks › Scripts › New script (or Record a new script, below).
  2. The editor opens. At the top: Run, Save and More… (check it for problems, edit it as JSON, export it with what it uses, read how scripts work). How a script runs explains it in one page.
  3. Before it starts sets the stage once: Stage mode, the layout, the deck, the web page. These are replayed quietly when you go back, so the screen is right at every step.
  4. Each step is a card with three lanes, in the order they happen:
    • Show: what happens on screen (chips: tap one to change it, + Add for more);
    • Say: the assistant's line ({notes} reads the slide's speaker notes), its face and its motion;
    • Next: what moves it on.
  5. The buttons on a step: ▶ try just this step, ↑ ↓ move it, ⋯ more (save its id, duplicate, delete).

Add a step (the wizard)

Add a step (at the end, or ⊕ between steps) asks three questions:

  1. On screen: a slide, a web page, something done on screen (clicks and typing, added on the card next), or nothing new;
  2. The assistant says: a line or the slide's notes, with a face and a motion;
  3. Moving on: the clicker, a phrase, a gesture, after some seconds.

Moving on

The Next lane says what moves a step on; whichever comes first wins:

  • The clicker or → (on by default) and a phrase (next, or your own words);
  • a hand gesture of the presenter (open palm, thumb up, swipe…; needs Follow the presenter);
  • automatically, some seconds after the step is done;
  • when something happens in the app (a video ends, a page changes, a route starts);
  • a jump to another step instead of the next one.

Choices (+ in the Next lane › A choice) jump elsewhere on other phrases or gestures: show me the live data → the live-data step. While a script runs, go back, back two steps, start over, repeat that and stop the demo always work, and the step dots on Stage list every step to jump to.

Record a new script

  1. Scripts › Record a new script.
  2. Use the app as you would in the demo: click widgets and buttons, type, press keys, scroll, drag, and click and type on web pages in web widgets. A recording bar stays on screen.
  3. Done. The recording becomes a script whose steps are your actions, with waits where you paused. Save it, or save and run it.
PasswordsPassword, payment and one-time-code fields are never recorded; replays stop there for you.

Interactive scripts

No timeline: the assistant greets you, listens, does what you ask from its list, and listens again until you say you're done. Scripts › New interactive script.

  • Things it can do (intents): each has phrases (show sales for {month}: {month} catches the words), an optional hand gesture or app event, a question for each missing word (Which month?), what it says, and its steps.
  • When nothing matches: the fallback steps; with Understanding (Settings › Assistant) a language model picks the intent instead.
  • Idle steps after some quiet, and end phrases (that's all).

Data, your Mac, and tasks from scripts

  • Data: load a CSV/JSON (or a SQLite query on the Mac) into the data widget, change the chart, have the assistant say a summary. Actions Load a CSV…, Change the chart, Summarize the data.
  • Your Mac: AppleScript, a Shortcut, JavaScript for Automation or a shell command (group This computer). Values go in as arguments, never into the code, and each piece of code asks you once before it runs.
  • Agent tasks: the action Run another task (group Agent) runs a task and shows its card; keep its result with as to use in the next lines.

Run, rehearse, share

  • Run in the editor, ▶ in the list, the start page's cards, or by voice. ▶ on a step tries just that step.
  • Presenter view (Settings › Stage) shows notes, what's next and a timer on your own screen.
  • Share: ⬇ downloads a bundle with everything the script uses; Import; Library; in a mesh, scripts are shared with your devices unless marked private.

Agent tasks: the list

Settings › Scripts & tasks › Agent tasks: every task, grouped, with ▶ (run it and watch), the sliders (edit), and, for your own, delete (or Reset, for a built-in task you changed). At the top: New task (guided), Teach me and Blank task.

Teach me

  1. Teach me (or New task › “I'll show you”). Give it a name, the ways you'll ask (words in braces become inputs) and the address it starts at.
  2. The agent browser opens with a red Teaching bar. Sign in if the site asks (sign-ins are kept; passwords are never recorded). Then do the task once, the way you always do: click the search box, type, press Enter, open the first result…
  3. When the answer is on screen, tap Read this part and click the part to read: the message, the list, the table. It's outlined as you hover.
  4. Done. It asks what to tell you from what it read, and which words you typed change each time: tick them and name them (search, person); they become inputs, asked for when you don't say them.
  5. The steps appear in the editor. Test (watch), fix what needs fixing, Save.
Rows of a listA click on a row of a list (a mail, a chat) is recorded by its place (“the first row”), not its words, because those change every time. To pick a row by its words instead, change the step to Click with the text.

The editor and inputs

  • Name and Ways to ask: one way a line. {person} in a line becomes an input filled from what you say (read the mail from Priya → person = Priya). Several ways help it understand you; Apple's on-device model also matches by meaning.
  • Inputs: for each, the question when it's missing (From whom?), a default (used when it's not said), a test value (for Test), and “a person”, which looks up their email and number in People.
  • It acts for me: asked before every run (unless you trust it), with your Question before acting (inputs filled in). Runs on my Mac: uses the agent browser (a phone asks the Mac). Share in the mesh: your other devices can get it.

Test, watch, fix

  1. Test (watch) in the editor (or ▶ in the list) opens a form with every input, filled with its test value; change any, then Run (watch). The values you ran with are kept for next time.
  2. The agent browser shows in a side panel: the page as the agent sees it, each step listed as it runs, ✓ with what it got (“208 characters read”) or ✗ with why, the element it clicks or types into ringed in red.
  3. To go slower: Agent › Library › Settings › One step at a time pauses before each step: Next step, Run the rest, Stop the task. Show the browser while tasks run watches every run, not only tests.
  4. Fix the step marked ✗ in the editor (often a selector or a wait), test again, Save.

Acting for you, People, sharing

  • Acting: a task marked “acts for me” (or that runs one that does) asks Shall I …? every time: Yes, Yes, always (trust it from now on), or No. Take trust back in Agent › Library.
  • People (Agent › Library › People): names with an email (mail, Teams) and a number with country code (WhatsApp). Inputs marked “a person” fill {person_email} and {person_phone} from here.
  • Sharing: tick Share in the mesh; your other StudioGens see it in Mesh › Shared and can get a copy.

Finding things on a page

Every click, type, wait and read needs to find something on the page again, next time, when the page may look a little different. From most to least reliable:

WayLooks likeUse it for
A role[role="listbox"], [role="option"], [role="document"], [role="main"]The big parts of web apps (Outlook, Teams, Slack, WhatsApp use them): the message list, a row, the message, the main area
A labelbutton[aria-label="Send"], [aria-label="Message body"]Buttons and areas named for screen readers; stable across languages less so
A test id[data-testid="search"]Pages that have them (your own pages: add them)
Its textClick Send, type into SearchButtons and fields with a fixed label
Its place[role="option"]:nth-of-type(2)“The second row”, whatever it says; loops over rows
Its id or path#topSearchInput, main > div:nth-of-type(3)Last resort: ids with long numbers and deep paths change when the site updates

How to find one: Teach me records the best it can for each click and typing; Read this part picks an area and gives its selector; in the editor you can try another choice and Test. Several choices with || are tried in order, so button[aria-label="Send"]||button[title="Send"] works on both versions of a page. In scripts on Stage there are more ways: the words on screen, a picture of an area, a description for the screen model, or your own trained detector.

Recipe: repeat over items in a list tested

Goal: open the first three messages one after the other, read each, and sum them up together. When: anything that repeats over rows: messages, search results, orders, tickets.

  1. Open a page at the inbox, waiting for [role="listbox"].
  2. Advanced step: start an empty collection: { "set": "all", "value": "" }
  3. Advanced step: for each of 1, 2 and 3: click that row by its place, wait for the message, read it, add it to the collection: 
    { "each": "1, 2, 3", "as": "n", "steps": [
  { "do": "agent.click", "args": ["sel=[role=\"listbox\"] [role=\"option\"]:nth-of-type({n})"] },
  { "do": "agent.wait", "value": "[role=\"document\"]", "args": ["ms=8000"] },
  { "do": "agent.read", "value": "[role=\"document\"]||#pane", "as": "read" },
  { "set": "all", "value": "{all}\n---\n{read}" }
] }
  4. Make the answer card from {all}: “These are three emails separated by ---. One item per email: title = sender and subject; detail = what they want.”

Variations: more rows: "each": "1, 2, 3, 4, 5". Only rows marked unread: read the list first (Read part of the page on [role="option"], one line per row) and let the card pick the unread ones, which needs no clicks at all. Over values you said: "each": "{people}" with … for Priya, Rahul.

Result on the practice inbox: “Contract sign requested by Friday; password reset needed; review time change asked”, one item per mail (picture in Test, watch, fix).

Recipe: repeat until nothing is left tested

Goal: press “Load more” until it's gone, then read everything. When: pages that show a few results at a time.

{ "until": "{more} is false", "steps": [
  { "do": "agent.click", "value": "Load more", "args": ["optional"], "as": "more" },
  { "wait": 1500 }
] }

optional makes the click carry on when the button isn't there, and "as": "more" keeps whether it clicked; the loop stops the first time it didn't (and after 1000 rounds at most). The next steps (a read, the card) run once it's all loaded. For a fixed number of rounds use { "repeat": "5", "steps": [ … ] }.

Recipe: search, open the first result, read it tested

Goal: read the mail from Rahul. When: anything that starts with a search.

  1. Open a page (inbox), wait for [role="listbox"].
  2. Type into a field Search, what to type {person}, Press Enter after.
  3. Pause 1 s (the list redraws).
  4. Click selector [role="listbox"] [role="option"] (the first row).
  5. Wait for [role="document"], then Read [role="document"].
  6. Make the answer card: “Sum up this email: who wrote, what it is about and what they ask for.”

On the practice inbox, with person = Rahul: “Two people are travelling on Wednesday. Can we move the quarterly review to Thursday afternoon, 3 pm?”

Recipe: stop when nothing is found tested

After a read, stop with a clear message instead of an empty card:

{ "if": "{read} is empty", "then": [ { "do": "agent.fail", "value": "There's no mail from {person}." } ] }

Or check what the page says (on the practice inbox a search for someone with no mail shows “No messages match”; the task then stops with “There is no mail from Zebedee.”): { "if": "{read} contains No messages match", "then": [ … ] }. Conditions can be joined: {count} > 0 and {read} contains invoice.

Recipe: slow pages, pop-ups and sign-ins

  • Slow pages: give Open a page a Wait until this shows, and put a Wait for something after clicks that load content. Waiting for the thing you need beats a fixed pause: it goes on as soon as it's there.
  • Pop-ups and banners: a Click on Close or Accept essential with optional, so the task carries on when there's none; or a site helper that clicks it for every page.
  • Sign-ins: the Site name on Open a page makes a sign-in page stop the task with “Sign in to Outlook once in the agent browser”; sign in there once and it's kept.
  • Robot checks (“unusual traffic”) stop the task and open the agent browser so you can answer them.

Recipe: elements whose text changes

Rows of a list, counters (Inbox (12)) and dates change every time. Find them by what doesn't change: the role and place ([role="option"]:nth-of-type(1)), a label ([aria-label^="Inbox"]: starts with), or the area around them. ^= starts with, *= contains, $= ends with.

Recipe: use one task's result in another

A task's card is kept with as, and its parts are reachable by dots: {next.headline}, {next.items.0.title}, {next.items.0.person}, {next.items.0.place}. The built-in Brief me for my next meeting does exactly this:

  1. Run another task My next meeting, kept as next.
  2. Advanced: { "if": "{next.items.0.person} is empty", "then": [ { "set": "card", "value": "{next}" } ], "else": [ … ] }
  3. In the else: Run another task Read the latest mail from someone with person={next.items.0.person}, kept as mail, then Make the answer card from Meeting: {next} Latest mail: {mail}.

Recipe: send something, safely

  1. Tick It acts for me, and write the Question before acting with inputs in it: send “{message}” to {person} becomes Shall I send “running late” to Priya?
  2. For mail, open the compose page with the values in the address: Open a page {outlook}/mail/deeplink/compose with More inputs ?to={person_email}, ?subject={subject}, ?body={message}.
  3. Click Send (selector button[aria-label="Send"]||button[title="Send"]).
  4. Test on yourself first: put your own address in People.

Script recipes

A slideshow that loops until a gesture

Steps “Slide 1”…“Slide 5”, each moving on automatically after 8 s; the last jumps back to the first (Next › jump); a branch on the presenter's thumb up jumps to the talk. Good for a lobby screen that waits for the speaker.

Say every row of a table

{ "do": "data.csv", "value": "samples/sales.csv", "as": "rows" },
{ "each": "{rows}", "as": "row", "steps": [ { "say": "{row.month}: {row.revenue} in revenue." } ] }

A long job while the assistant keeps talking

An action with In the background on (an export, a report task), named; the next steps keep presenting; { "await": "export" } before the step that needs it; its then steps say “The export is done”.

Fetch something live in the middle of a talk

The action Run another task (What's my day?, Flight status) as a step: on Stage its card shows over the slides while the assistant reads it, and the talk carries on at the next step.

An interactive helper that runs tasks

An interactive script whose intents each run a task: show the mail from {person} → Run another task with person={person}; the assistant listens again after each.

Troubleshooting

What you seeWhat to do
A step ✗ “Couldn't click…” / “No field…”The selector or text no longer matches. Teach that part again (Teach more steps), or give two choices with ||.
“I couldn't read anything on that page”The read found nothing: check What to read, add a Wait for something before it, or read [role="main"].
The card has the wrong factsRead a smaller area (only the message, not the whole page), and be specific in What to tell me. Watch it: the panel shows what was read.
“Sign in to … in the agent browser”Agent › Library › Agent browser, sign in once, Done, run again.
It works when watched but not hiddenPages behave the same (same size); usually it's timing: add a wait.
A script step doesn't find its elementUse “Its text on screen”, a picture of the area, or the screen model's description instead of the recorded element.
Something elseSettings › Logs (debug mode) shows each step; share the log.
