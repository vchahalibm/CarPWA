1. Talking freely with the assistant

Today, what you say is matched to a command or a task; if nothing matches, the model only picks a command, and otherwise you get “Sorry, I didn't catch that”. With gpt-oss on the Mac, anything else can simply be a conversation, in the Assistant widget, on Stage (the 3D assistant speaks and gestures) and on the Agent and home screens.

One conversation, with tools

what you say ──► 1. exact phrases and task wordings (instant, as now: “next slide”, “what's my day”)
              └► 2. otherwise the model, with the conversation so far and a list of what it can do
                     answers with ONE of:
                       { "do": "task",    "id": "cal.today", "inputs": { "day": "Monday" } }   → run it, its card in the chat
                       { "do": "command", "id": "info.weather" }                              → run it, its card in the chat
                       { "do": "script",  "name": "Keynote" }                                 → start it (asks first on Stage)
                       { "do": "watch",   "draft": { … } }                                    → offer a watcher (section 6)
                       { "do": "reply",   "text": "…" }                                       → just talk
  • The same rules as now: anything that sends, books, posts or removes still asks first; private screens stay private; while driving, answers stay short and nothing distracting shows.
  • It knows what you're looking at: the last few cards and their items (“tell me more about the second mail”, “reply to her saying I'll call”), the slide on Stage, the screen that's open. A follow-up refers back without repeating names.
  • Memory: the conversation since you last went quiet for 15 minutes (then a one-line summary is kept); “forget that” clears it. It stays on the device; with Claude chosen, it's sent to Claude only for that turn.
  • Speaking while it thinks: the built-in engine will stream words as they come; the reply voice speaks sentence by sentence (Phonon already plays in pieces), the avatar's lips and gestures follow, Stage shows captions. A first word in about a second, not after the whole answer.
  • Phones: DriveGen talks to the Mac's model (as now for cards); on mobile data a short answer is still quick, since only text travels.
  • Where it shows: the Assistant widget becomes a chat (your words, its words, cards inline); the Agent screen gets the same thread above the cards; on Stage the reply is spoken with captions and cards float beside the avatar (Peek).

How others do it: ChatGPT, Claude and Gemini apps decide between answering and calling a tool in one model call (function calling); voice assistants (Alexa, Siri) keep fixed intents first and fall back to an LLM only recently. The proposal does both: fixed phrases stay instant and predictable, the model handles the rest.

2. Answers as cards, wherever you ask

Today a command such as weather opens its own screen, except on the Agent home and on Stage (Peek turns a few screens into cards). Proposed:

  • Every command that answers something (weather, time, ETA, battery, messages, who's around, what's playing, a route summary) gives a card: the same card format as tasks (headline, items, a picture where it helps: the weather's hourly strip, the route's map thumbnail), spoken as now.
  • The card appears where you are: the Agent and home screens (big), the Assistant chat, Stage (beside the avatar). A Open button goes to the full screen when you want it; opening a screen only happens by tapping or saying “open the weather”.
  • Cards go on the timeline like task results, so “what was the weather this morning” finds it.

3. The camera widget's own on/off

A small switch on the widget itself (and “camera off”, “camera on” by voice): off stops the camera (the light goes out) and shows a still “Camera off · tap to turn on”; on asks for the camera if needed (the permission sheet if it was turned down). The widget stays where it is; no editing the layout. Each camera user (vision, people tracking, mocap) already takes and releases the one shared stream, so off is simply this widget releasing it.

5. Watchers: the design

A watcher is a task that runs on its own, again and again, and tells you only when something it's watching for happens.

What it can watch for

KindExampleHow it decides
New items in a listNew Slack mentions, new Teams chats, new mail from Priya, new posts by an X account, new job postingsEach row gets an identity (a hash of its stable words: sender, title, time); rows not seen before are new. Never re-reports the same item.
Changes in a part of a pageA policy page, a status page, a product descriptionThe text of the chosen part, compared with last time (ignoring whitespace, dates, counters and parts you mark “ignore”); the difference highlighted
A value crossing a linePrice below 500, stock above 0, a delivery status changing to “Out for delivery”The number or word read each time and compared with your condition; tells once when it crosses, again only after it crosses back
Words appearing“sold out” gone, “applications open”, your name mentionedContains / doesn't contain, in the chosen part
Something that matters, judged by the model“Tell me if anything in my mail needs me today”, “only important changes”The new items or the change go to the model with your rule; it answers yes/no with a one-line reason. Used after the cheap checks above, so the model runs only when something actually changed.
A visual change (fallback)Pages with no usable text (a chart, a map)A screenshot of the area compared with the last one; tells above a threshold

How it checks

  • Polling (any website): on a schedule (every 5 minutes to daily, with a little randomness so it isn't robotic), it opens the page in the agent browser (its container, so sign-ins work), runs the steps (search, click a tab), reads the part, decides, closes. Uses the same steps, sites notes and selectors as tasks; uses a browser only while checking; respects the 3-at-once limit (tasks first, watchers wait).
  • Live (pages that update themselves: Slack, Teams, WhatsApp, Outlook, X): the page stays open in a hidden browser and the bridge watches it (a DOM observer); new rows are noticed within seconds, with no reloading and far less load on the site. Costs ~150–300 MB per open page, so live watchers belong on Workers (or a Mac with memory to spare).
  • Official feeds first: where a site has RSS, an email notification you could forward, or a public JSON, a watcher can read that instead of the page (the app suggests it when it finds a feed link).
  • When something's wrong: signed out → it pauses, tells you once (“Slack watcher needs you to sign in: Sign in from here”); a robot check → pauses and asks you to answer it; the page changed so much the part is gone → it tells you and offers to pick the part again. Failures back off (5 min, 15, 1 h), never hammer.

A watcher, as stored

{ "format": "studiogen-watcher", "version": 1,
  "watcher": { "name": "Acme price", "site": "https://shop.example/acme-widget",
    "steps": [],                                  // optional: the same steps as a task (sign-in container, clicks, searches)
    "read": "[data-test=price]",                  // the part (picked, never typed by hand unless you want to)
    "kind": "value", "condition": "below 500",    // new | changes | value | contains | ask | visual
    "ignore": [".ad", "time"], "every": "30m", "quiet": "22:00-07:00",
    "tell": { "card": true, "speak": "important", "phone": true, "digest": "18:00" },
    "runOn": "worker:watch-1",                    // this Mac, a Worker, or any of mine
    "ask": "" } }                                 // the model's rule, for kind "ask" or as a final filter

What you get

  • A watch card on the Agent screen (and the timeline): what changed, the new items, the old → new value, a thumbnail of the area; buttons Open page, Mute this watcher for a day, Not important (teaches the filter).
  • A small notification on the home screen and Stage (a toast with the headline, not a screen change), a push to DriveGen (through StudioGBee when the phone is away), spoken only for what you marked important, never while presenting unless you allow it.
  • A digest instead of single notes, if you prefer: “Since this morning: 6 new Slack mentions (2 for you), Acme price down to 489, the policy page changed its refund section”, written by the model and read by the assistant.
  • A Watchers list: each one's last check, last change, next check, where it runs, on/off, edit, “check now”.

6. Making a watcher, the friendly way

  1. Watch this: in the agent browser (or Sign in from here on a Worker), open the page and tap Watch something here. Tap the part (the bridge's picker, as in Teach me). The app looks at what you tapped and suggests the kind: a list → “new items”; a number → “price or value”; a block of text → “changes”; then shows what it reads now (“Price: 529”) so you can see it picked the right thing. Choose how often, how to be told, where to run. Done in three taps.
  2. Say it: “watch the Acme widget page and tell me when it's under 500”, “keep an eye on Slack for anything from Priya”, “tell me when my parcel is out for delivery”. The model drafts the watcher (the build prompt gets a watcher section); the app opens the page, finds the part, shows the current value and asks “Watch this every 30 minutes?”
  3. Templates for the common ones, no picking needed: New Slack mentions · New Teams chats · New mail from someone · New mail matching words · New WhatsApp messages from someone · New posts by an X account · Page changes · Price drop · Back in stock · New job postings on a careers page · A delivery status.
  4. Check it before it runs: a check run shows what it reads now, what it would report if the page changed (it simulates one), and how noisy the part has been (it reads twice a minute apart: if it differs already, it suggests ignoring the changing bits, such as a clock or an ad).
  5. Fix it later: on a failed check, Show me opens the page where it stopped and you tap the part again (as for tasks today).

7. Where watchers run: this Mac, Workers, the feed

 Watch Worker (OrbStack, its own sign-ins)        StudioGen on your Mac                    DriveGen (phone)
   live: Slack, Teams, WhatsApp, X pages            the feed: watch cards, digest            notification + card
   polling: websites on schedules                   Watchers list, editing                    (through StudioGBee
   the model: your Mac's (through the mesh)    ──►  the model (gpt-oss, built in)       ──►    when away)
   events: sealed, through the mesh / bee           notifications on home, Stage
  • Any StudioGen can run watchers; a Watch Worker is simply a Worker you assign them to. Making one: Mesh › Workers › + New Worker › “for watching” (OrbStack recommended: always on, its own sign-ins, can keep pages open).
  • A worker sends events (small: watcher, kind, items, a thumbnail) to your StudioGens and devices over the mesh, sealed; if they're offline, StudioGBee keeps them and DriveGen gets a push. The feed on each device shows them as cards.
  • The model (for “ask” rules and digests) is the Mac's, through the mesh as now; a watcher that only compares text needs no model at all.
  • Watchers move between machines with a tap (the definition travels; sign-ins don't: signing in on the new one is part of moving).

8. Limits, manners and safety

  • Sites' rules: watchers check gently (minimum intervals per site, randomness, one page at a time per site), reuse your own sign-in, and never solve robot checks themselves. Some sites (X, LinkedIn) forbid automated reading in their terms; the app says so on those templates and suggests low frequency or official notifications.
  • Only my devices: watchers of signed-in pages are private (like tasks); what they report goes only to your devices. A watcher of a public page can be shared in the mesh like a task.
  • No passwords: as for tasks, never recorded or typed by a watcher; signing in stays yours.
  • Resources: on a 24 GB Mac with gpt-oss loaded, a few polling watchers are fine; live pages and many watchers go to a Worker. The Watchers list shows memory and the load.

Questions for you

  1. Talking freely: should it be on everywhere, or only when you start with the wake word / open the chat (so a meeting's chatter isn't answered on Stage)?
  2. Memory: keep only the current conversation (forgotten after 15 quiet minutes), or remember facts you tell it across days (“my manager is Priya”) on this device?
  3. Cards: should answering commands never open their screen (only Open on the card), or open the screen when you're already on the dashboard?
  4. Watch notifications: a card and a quiet toast by default, spoken only for “important”, a daily digest at a time you choose: is that right?
  5. Which first templates matter most to you: Slack mentions, Teams chats, Outlook from someone, WhatsApp from someone, X account posts, page changes, price/stock?
  6. Watch Workers: one dedicated Worker for all watchers, or a choice per watcher?
  7. X (Twitter): read your logged-in timeline/lists despite its terms (low frequency, your account), or only public profiles, or skip?
